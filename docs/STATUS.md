# 当前能力与待办

整理日期：2026-10-23。项目用于求职作品展示，目标是可实际使用的旅行助手；当前代码具备完整本地流程和可部署配置，尚不能声明已完成容器或公开生产部署验收。

## 已实现

- 自然语言和详细设置规划，攻略正文、链接与截图来源，地点优先级和地图候选核实。
- 后台生成、真实交通时间线、有界冲突修复、逐日阅读、明暗主题和可关闭动效。
- 景点、餐厅和住宿的编辑、替换及助手建议；版本保存、方案预览、撤销和恢复。
- 费用参考、用户酒店报价、参观准备、部分官方规则来源和数据新鲜度提示。
- 景点旁按需查询美团门票与商品跳转链接，可选查询日期；供应商内容与行程预算分开，不自动下单。
- 查票窗口内直接阅读故宫、国博、天坛及颐和园的已复核官方常规须知，含来源、复核日期、票种/入场细则；过期后隐藏具体规则，不代替实时公告或预约凭证。
- 录入固定场次或入场时间段，复用已保存交通预览早到等待、晚到冲突；满足条件时提供提前出发方案，确认后保存可恢复版本。
- 用户预订记录与实付总额替换对应人数的门票参考费；取消、累计已退金额及未退费用单列，编辑和 Agent 修订不能伪造或丢失记录。
- 入场冲突可预览同日换序；允许跨日时可移动未预约的灵活景点，重新查询变动路段，仅可采用已核对可安排的方案。
- 本地一键启动、隔离的六步离线演示验收、SQLite 一致性备份，以及 Compose、Nginx 和手动容器验收工作流配置。
- 默认部署依赖已分离与 OpenAI 2.x 冲突的旧 HelloAgents SDK，保留按需导入的历史代码；独立环境安装和无旧 SDK 启动检查通过。真实 Render 镜像构建仍需线上验收。
- 任务幂等、进度恢复、取消、共享限速、资源协调，以及不确定信息的明确降级。

具体机制见[架构](ARCHITECTURE.md)和[核心设计](CORE_DESIGN.md)，已验证范围见[评测](EVALUATION.md)。

## 求职演示优先级

入场时段、用户预订记录、预算与有界冲突调整已串联。外部跳转和录入时间本身均不代表预订成功；用户记录也不等于已独立核实平台订单。

2026-10-22 已补充完整主题需求、未来示例日期和未发送文字的刷新恢复；本地检查脚本与[演示说明](DEMO.md)可直接使用。两条公开生成样本与本阶段回归见[评测](EVALUATION.md#2026-10-22-展示版检查)。公开部署仍未完成。

1. 固定少量公开场景，演示从输入、生成到修改、撤销和恢复的完整流程。
2. 用实际报告说明时长、查询覆盖和失败行为，保留失败案例及修复思路，不把单次成绩写成生产 SLA。
3. 明确区分模型建议、地图登记信息、用户报价和官方政策参考；让缺失数据有解释与后续操作。
4. 确定公开体验入口的使用范围、访问方式和成本上限，再做部署验收。

## 未完成或覆盖有限

| 范围 | 当前边界 |
| --- | --- |
| 实际入场与预订 | 部分场馆规则参考和用户记录；没有全面实时余票、订单同步、OTA 房源库存或自动订房能力 |
| 内容准确性 | 有身份与事实约束，仍需扩展地点、季节、临时公告和复杂用户要求的覆盖 |
| 性能 | 有小样本和局部验证；没有足够证据证明公网 p95、吞吐和长期稳定性 |
| 账号与部署 | 已提供默认回环地址绑定、邀请访问、持久卷的容器配置；本机无 Docker，镜像/容器、HTTPS 和公网运行未验收。正式账号与跨设备同步未实现 |
| 运维 | 已有本地故障和恢复验证；生产监控、持续负载及跨主机协调仍需确认 |
