# 交互接口资源保护与繁忙反馈

上一阶段提交恢复已完成代码和故障验证，本阶段继续补齐主后台队列以外的调用入口。生产目标仍未完成，也未把浏览器标识或地址限制当作正式账号鉴权。

## 实际缺口

后台规划任务已有接收上限和执行租约，但自然语言理解、旧版直接规划/对话、推荐、备选、OCR、网页提取、补充事实、路线校验等 HTTP 入口没有同一套容量控制。地点/照片/天气查询也能独立消耗资源。部分旧地图方法同步执行，会阻塞异步事件循环；旧健康检查会初始化模型或 MCP 工具，甚至给出固定工具数量。

本轮在四组路由统一挂接 `protect_request`，生产主应用始终配置 `RequestGate`。根据已匹配路由模板分类，防止把用户提交的具体路径文本当策略依据。读任务、SSE、取消、后台任务接收不占交互槽位：后台任务接收仍受既有事务式队列保护，不让交互繁忙阻断进度和取消。

## 行为及默认值

共享存储为 `backend/var/request-gate.sqlite3`，适用于同一机器、共享同一文件和相同配置的 worker。`BEGIN IMMEDIATE` 将并发检查、自然分钟计数和租约写入放在同一事务中。

| 池 | 全部署同时在途 | 同一来源地址同时在途 | 同一来源地址/自然分钟 | 全部署/自然分钟 |
| --- | --- | --- | --- | --- |
| 模型、OCR、攻略提取、复杂路线/事实操作 | 2 | 2 | 12 | 60 |
| 地点、图片、天气、旧地址路线查询 | 12 | 6 | 120 | 600 |

这些参数可通过 `.env.example` 的 `HTTP_*` 调整，不是生产压测推导的最优值。后台规划的 2 个执行槽位属于另一套队列，不包含在这张表中；单个请求内部可能多次调用模型或地图。分钟窗口是自然分钟，不是滚动60秒；它限制 HTTP 操作数量，不代表供应商 QPS、token 或计费额度。

- 超限在业务调用前返回 HTTP 429 与 `Retry-After`；占用满时提示至少等3秒再试，频率额度耗尽时按当前窗口剩余秒数提示，不保证等待结束必有空位。
- 来源使用 ASGI client 地址，不直接读取用户给的 `X-Forwarded-For`，不使用可自建的浏览器 owner ID 作为反滥用身份。地址仅以摘要保存，但不称为不可识别的匿名数据。公网反向代理必须明确限制可信代理并清理转发头；共享出口用户会共用来源额度。
- 60秒租约按三分之一周期续期，完成/取消释放。SQLite提交期间的取消会等线程结束，再按预先知道的令牌清理；不会丢失“已提交但未收到许可回执”的占用。无法续期时取消所属请求，不继续假定持有许可；无法清理时依靠租约到期。外部服务已收到的请求及不可强制终止的同步调用不能据此保证立即停止。
- 协调存储不可用时返回503并停止新调用；`/ready` 新增本地 HTTP 协调存储检查。健康检查只报告本地配置及 `upstreams: not_probed`，不初始化模型/MCP或宣称供应商可用。
- 旧地图及旧引擎同步调用移入线程池，地图服务初始化加锁以避免多个请求同时启动多份 MCP 实例。这没有补齐旧地图封装中的空解析结果，不能将线程池修复称为旧地图功能正确率修复。
- 前端统一解析 HTTP 错误和重试秒数。需求理解、攻略提取、OCR、推荐/搜索、保存请求都能保留服务端说明；不再把限流误显示成空候选或普通断网。临时失败的图片请求不永久缓存在当前页面，后续重新进入日期可再次尝试。
