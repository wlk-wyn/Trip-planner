## Agent 如何工作

默认引擎位于 `backend/app/agents/travel_agent.py`，由 LangGraph 管理有边界的「模型决策 → 工具调用 → 观察结果 → 校验/修复」循环。模型自主决定是否搜索景点、酒店、餐厅或短期天气（同一轮可并行发出多个查询），也可直接回答不需要修改行程的问题。新地点必须来自高德 Web Service 的真实查询；模型最终只写地点 ID、停留时长和理由，名称、地址、坐标由程序按 ID 回填，餐厅按当天路线自动匹配；生成结果经结构和地点校验，失败时会把错误反馈给 Agent 重试。最多 5 轮工具调用、2 次修复，以控制延迟和成本。

表单是初次目标输入，结果页对话会携带当前行程和最近消息，让 Agent 在已有行程上继续工作。行程、原始攻略和最近对话保存到后端本地 SQLite；同一浏览器关闭后可从“我的旅行”继续。浏览器 localStorage 中的随机标识隔离旅行记录，目前没有账号登录和跨设备同步。旧的 sessionStorage 行程在结果页读取时会自动迁移。手动编辑和 DIY 功能仍可使用。

旧的固定并行查询版仍在 `backend/app/agents/langgraph_planner.py`，可通过 `PLANNER_ENGINE=langgraph` 切换；`helloagents` 是另一个旧版备选。默认是 `agent`。

## 技术栈

- 前端：Vue 3、TypeScript、Vite、Ant Design Vue、高德地图 JS API
- 后端：FastAPI、LangGraph、LangChain、DeepSeek 兼容接口、高德 Web Service
- 地点数据：高德 POI 查询；天气仅使用可获得的短期预报，不保证开放时间、票价、餐厅营业状态

## 本地运行

1. 在 `backend/.env` 配置 `AMAP_API_KEY`、`LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL_ID`。可参考 `backend/.env.example`，不要提交真实密钥。
2. 在 `backend` 目录安装 `requirements.txt`。Windows PowerShell 中设置 `$env:PYTHONIOENCODING='utf-8'`，再启动 `uvicorn app.api.main:app --host 127.0.0.1 --port 8000`。
3. 在 `frontend` 目录执行 `npm install` 和 `npm run dev`，打开 `http://127.0.0.1:5173/`。

后端进程需要能访问已配置的模型与高德服务。在 Codex 等受限执行环境中启动的进程也可能继承网络限制；若接口提示“高德服务网络连接失败”，应先区分执行环境限制与供应商返回的权限、配额错误。经授权在正常网络环境启动后端即可恢复这类连接问题。`/ready` 与 `/api/map/health` 只检查本地就绪和配置，不代表上游查询成功；可通过 `/docs` 用公开示例地址调用一次 `/api/map/route` 验证完整链路。

主要接口：`POST /api/trips/plan-runs` 在后台生成并保存新行程，`GET /api/trips/runs/{run_id}/events` 以 SSE 推送进度（页面使用这两个）；`POST /api/trip/plan` 是保留的同步生成接口；`POST /api/trip/chat` 按当前行程继续对话；`GET /docs` 查看全部 API。

运行测试：在 `backend` 目录执行 `python -X utf8 -m unittest discover -s tests -v`；前端执行 `npm run build`。

项目结构与数据流见 [docs/ARCHITECTURE.md](ARCHITECTURE.md)。

## 本轮新增：攻略来源、旅行保存与撤销

- 正文、链接提取与截图 OCR 保存为独立攻略；截图支持直接识别整张，裁剪仍可选。
- 自动提取地点并查询高德，重名和分店需要确认。地点可设为必去、可选或忽略，默认可选。必去与忽略约束在生成、对话调整和手动保存时校验。
- POI 查询保留地点 ID；同名地点按 ID 和坐标匹配。后续对话继续读取原攻略，明确要求修改某一天时保留其余日期。
- 首页“我的旅行”可打开多份行程。Agent、手动与 DIY 修改均保存版本，结果页显示差异摘要，支持撤销和恢复历史；恢复会保留已有记录。
- 保存使用 `backend/var/trips.sqlite3`（目录已由现有 Git 规则忽略）。备份该文件即可保留本地旅行数据。SQLite 适用于当前本地版本；服务重装时需保留文件。
- 尚未实现跨设备账号同步或中断中的模型任务恢复。刷新可恢复已保存结果，未完成的生成仍需重试。

新增接口位于 `/api/trips`：创建／列表／读取、`/{id}/versions`、`/{id}/restore`、`/{id}/chat`、`/references/analyze`。保存接口要求 UUID 格式的 `X-Trip-Owner` 浏览器标识；该标识应当保密，它不是完整的账号认证系统。上线多人使用前应接正式认证。

本轮使用离线模型与地图替身验收来源去重、分店确认、必去约束、原攻略保留、指定日期修改、版本冲突、恢复与浏览器标识隔离。真实模型端到端联调单独进行，不能以离线测试代替。

## 下一阶段已实现：每日时间校验与费用状态

- 详细设置支持每日出发／结束时间和每段交通缓冲；结果页可逐日编辑，并为景点填写固定预约。
- 服务端使用高德 Web Service 查询步行、自驾或公共交通的时间与距离，按酒店、早餐、景点、午餐、晚餐及返程形成时间轴；零食默认放在景点之后。成功路线缓存15分钟，最多512条；单次校验总等待上限40秒。
- 用餐假设为早餐30分钟、午晚餐各60分钟、零食30分钟；景点时长为建议值。预约晚到、超出日程窗口会显示冲突；失败／无坐标／超时标为未核实，后续时间不显示为精确时间。交通结果只代表查询时条件，不预测出行日期的班次与路况，营业时间仍需复核。
- Agent 在有时间冲突时有限重试，保留必去地点、已有固定预约和手动填写费用；修复次数耗尽时返回带冲突标识的草稿。移除了按四个景点上限静默删除地点的旧逻辑。明确指定某一天的修改仍保留其他日期。
- 手动、DIY及路线修改在保存前重新校验；旧行程可用“重新校验时间”，并保存为可撤销版本。地图交通摘要复用服务端结果，不再用直线距离补成看似可靠的交通时间。地图连线仍为示意，不是导航路线。
- 未知价格为null，估算与用户提供价格分别展示；历史零价格视为未知，明确填写0才显示免费。“已知费用小计”包含已列门票、单人餐费及住宿，并标明未知项和另计交通，不提供完整预算承诺。用户提供的价格没有独立核实。

新增接口：`POST /api/trips/{id}/validate`，请求携带`base_version`；并发冲突返回409。

验收使用离线地图／模型样例，以及浏览器中的明确标注示例，覆盖路线解析、预约与超时、交通故障、锁定地点、费用迁移、版本校验与恢复。已验证真实 DeepSeek 需求理解，并用北京三天行程验证高德交通：19 段均取得查询耗时；完整模型生成与营业时间、预约、价格仍未完成生产级联调。自动区域分日、开放时间规则与路线顺序优化仍是后续工作。

## 界面与明暗模式

首页采用旅行工作台：直接填写目的地、出发与返程日期，搭配旅行想法输入、城市漫游／亲子时光／自然放空主题入口，以及实时联动的旅行草稿卡。草稿路线为明确标注的示意，生成后查看真实地点与路线。攻略和详细设置按需展开。结果页沿用相同配色，攻略来源默认收起，占位图片改为中性图形。

右上角可切换浅色／暗色，默认浅色。偏好保存在当前浏览器的`tripTheme`，刷新时提前应用，多个标签页也会同步切换。Ant Design 控件与自定义卡片共用主题，原有规划、编辑、版本和时间校验功能保留。本轮进行了1280px桌面和390px手机布局、主题切换与刷新记忆的浏览器验收，并通过前端生产构建。

排版参考：[Apple官网](https://www.apple.com/)的简洁导航与留白，以及[ChatGPT](https://chatgpt.com/)的居中对话输入。仅参考界面组织方式，不复用其品牌资源。

旅行工作台的已填写条件会随自然语言需求传给需求理解流程，新描述中的更改优先；城市和日期完整且没有补充想法时，可直接使用已有表单规划流程。主题入口只填入想法，不自动发起模型请求。

结果页以每日行程为主：日期卡片一次展示一天，支持方向键及前后日按钮，并提供约 420ms 的淡入滑动动画；独立“切换动效”开关默认开启并保存偏好，仅该切换覆盖系统减少动态效果设置。统一时间线显示游览、餐饮、住宿与交通；地点详情、时间依据和地图按需展开，编辑时自动打开地点控件。图片／PDF 导出副本包含全部日期，不改变当前浏览日期。

交通可靠性：默认按每个后端进程 1 请求/秒限速，网络/短期限流最多尝试 3 次；密钥、权限和日额度错误不盲目重试。公交无方案时查询真实步行路线，仅在步行距离不超过 2 公里时采用并显示实际方式，较长路线仍明确失败。查询结果保留时间与失败原因，禁止用直线距离估算或用模型编造耗时。多进程部署需要共享限流，当前进程内限流不构成生产部署保证。

结果页显示交通查询覆盖率；交通缺失或时间冲突时明确标为草稿。游览/用餐时长为建议，预计到达时间为计算结果；未知价格不显示成零预算。营业时间、实时预约和票价官方数据、节假日规则，以及自动缩减/换序后可行性验证仍需补齐，当前系统不能承诺可直接执行或预订的生产级行程。

地点编辑已统一到“编辑行程”：景点、餐厅和酒店可搜索新增或替换，餐厅/酒店可移除；新增餐饮可指定早餐/午餐/晚餐/加餐，同一餐次已有安排时提示从现有餐厅替换。每天均有三类推荐入口，可按偏好询问助手或换一批；模型只排序高德候选 ID，未知 ID 丢弃，名称/地址/坐标沿用查询数据，未知费用保持空值。推荐不会自动修改行程，选择后进入可取消的草稿，保存重新校验交通并生成版本。全行程 Agent 对话仍在已保存状态使用；编辑草稿中的地点推荐可独立使用。

### 2026-10-10 性能与体验优化

依据 [性能与体验调研](PERF_UX_RESEARCH_2026-10-10.md)，本轮的重点是缩短等待时间，并让等待过程看得见。

- **生成更快**：
  - 模型最终只输出精简行程（地点 ID、停留时长、理由），餐厅由程序匹配。
  - 时间冲突用 patch 只修改冲突日期，不再整份重写。
  - 同一轮可以并行发出多个搜索。
  - 最终轮保持同一套工具，前缀缓存可以命中。
  - temperature 默认 0.3；模型调用有超时（`LLM_TIMEOUT`）和重试上限。
  - 可选的 `LLM_FAST_MODEL_ID` 用于需求理解、攻略提取和推荐排序。
- **进度可见、刷新不丢**：
  - 首页改为后台任务，通过 SSE 显示实时阶段：搜索的关键词、写到第几天、已核实 x/y 段交通。
  - 可以取消；刷新或离开后回到首页会自动接回进度；完成后自动保存并跳转。
  - 对话和单日优化也从 1.2 秒轮询改为 SSE，断开时自动退回轮询。
- **地图与网络**：
  - 高德请求共享连接；路线限速不再持锁等待。
  - 地点搜索缓存 6 小时，路线缓存默认 6 小时（`ROUTE_CACHE_TTL_SECONDS`）。
  - SQLite 开启 WAL，阻塞读写移出事件循环。
- **页面**：
  - 去掉生成后的 500ms 等待；版本记录与地图并行加载；保存后地图只更新标记；不再弹出“地图加载成功”。
  - 配图优先使用高德 POI 照片，找不到时不再显示与地点无关的通用风景图。
- **观测**：后端日志会记录每次模型调用的耗时、输入、缓存命中和输出 token。配置 `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` 并安装 `langfuse` 后，可以查看完整链路。

**实测**（本机，真实 DeepSeek 与高德，`AMAP_ROUTE_QPS=1`，单次运行）：

| 场景 | 总耗时 | 模型调用 | 交通核实 | 结果 |
| --- | --- | --- | --- | --- |
| 杭州 1 天 | 19 秒 | 2 轮并行检索，1 次修复 | 8 段 | 7/7 段已核实，可行 |
| 北京 2 天 | 27 秒 | 6 次，每次 1–3 秒 | 12 段约 13 秒 | 11/11 段已核实；第 1 天经 2 次 patch 修复后仍超出 1 分钟，按设计标为冲突草稿 |

北京行程的最终输出只有 567 个 token，此前估计是 4–6k。从第 4 次模型调用起，前缀缓存命中率超过 90%。这两次都是单次运行，没有做多次统计；也没有在同一环境下测量改动前的耗时，此前的数字是按代码推算的。现在最大的耗时是路线查询（约等于路段数 / QPS），确认高德账户配额后调高 `AMAP_ROUTE_QPS` 的效果最直接。

后端离线测试共 73 项（本轮新增 7 项：精简输出回填、未知 ID 拒绝、patch 修复、新建任务保存一次且按用户隔离、失败原因透传、SSE 完整链路），前端生产构建通过。

**前端包体积**：应用入口从 1.06 MB 降到 85 KB，但 Ant Design 拆成了单独的 879 KB vendor 块，所以首次加载的总量没有明显变化。好处是发版后 vendor 块可以继续使用浏览器缓存。要真正减小体积，需要把组件改为按需引入。

### 2026-10-10 拖拽编辑与天气备选

- **拖拽调整**：进入“编辑行程”后，每天上方会出现排列面板。
  - 拖动景点调整顺序；拖到页面上方的日期标签，就移到那一天。
  - 手机和键盘可以用 ↑↓ 按钮和“移到第 N 天”下拉框。
  - 可以锁定景点；锁定或有固定预约的景点不能移动。
- **草稿撤销**：编辑过程中，“↶ 撤销一步”或 Ctrl+Z 可以逐步撤回地点调整，最多 50 步。撤销会回到上一次地点调整之前的状态，期间改过的文字也会一起撤回。
- **保存后自动优化**：默认勾选，偏好保存在浏览器里。保存后会对增删或调整过顺序的日期运行 OR-Tools 排程，锁定项和预约位置不动；多个日期合并为一次任务、一个可撤销版本。不需要时可以取消勾选。
- **天气与雨天备选**：结果页上方的按钮会读取高德短期预报（约 4 天）。
  - 有雨雪的日期，为未锁定的户外景点给出 5 公里内的室内候选（博物馆、展览馆、美术馆、科技馆、商场）。
  - 点选后只进入编辑草稿，保存时重新校验时间。
  - 超出预报范围显示“暂无预报”，不推测远期天气。
  - 室内户外优先按高德分类判断；旧数据没有分类时按名称判断，判断不出来就不给建议。

新增接口：`GET /api/trips/{id}/weather`。另外，`POST /api/trips/{id}/runs` 的优化任务新增 `dates` 字段，可以一次传入多个日期。

验证：
- 后端离线测试 77 项通过，本轮新增 4 项：室内户外判断；雨天只为未锁定的户外景点给出候选并排除已有地点；无预报或晴天不给建议；多日期优化生成一个版本。前端生产构建通过。
- 用真实高德接口调用了天气检查（杭州当天为晴，不触发建议）。另外把预报替换为“中雨”，用真实附近搜索验证候选：西湖周边返回了 1 公里内的陈列馆和印学博物馆。
- 拖拽、撤销和保存后自动优化只通过了类型检查和构建，还没有在浏览器里实际操作验证。

已知局限：
- 雨天候选在多天之间没有去重，连续雨天可能推荐同一个场馆。
- 没有接入历史同期气候。
- 撤销只覆盖地点调整这类操作，单独修改文字不会生成撤销步骤。

### 2026-10-10 规则校验、评测与出行准备

- **规则校验**：不调用模型或网络，由程序直接检查：
  - 重复景点、重复餐厅
  - 缺午餐或晚餐
  - 单日景点超过 6 个、单个景点停留超过 6 小时
  - 坐标不在国内，或离行程中心超过 80 公里（可能匹配到了同名地点）
  - 缺住宿、中途换酒店
  - 用户在补充说明里写了预算（如“预算1500元”）时，对比已知费用

  严重问题和警告并入结果页“行程可靠性”区域，轻微提示折叠成“小提示”。接口：`GET /api/trips/{id}/checks`。
- **出行准备**：结果页的“出行准备”按钮会生成一份清单：
  - 预约提醒：已设的固定预约；博物馆、纪念馆、剧院、主题乐园等常需预约的场馆，按出行日期倒推建议确认日期，时间已过则显示“建议尽快确认”。提醒只按场馆类型推断，具体规则请以官方渠道为准。
  - 住宿汇总：按酒店合并入住晚数。
  - 打包清单：根据户外景点和短期预报（雨具、保暖、防暑）生成。

  勾选进度保存在当前浏览器。接口：`GET /api/trips/{id}/prep`。
- **评测脚本**：在 `backend` 目录运行。
  - `python -X utf8 -m eval.run_eval score`：离线给本地全部行程打分，不调用接口。
  - `python -X utf8 -m eval.run_eval run [--cases id1,id2] [--limit N]`：用 `eval/cases.json` 中的 12 个中文用例真实生成行程并评分。

### 2026-10-10 价格与开放时间

此前价格大多显示“未知”，原因有两个：地点搜索用的是高德精简模式（不返回价格），而且核实地点时会主动清空价格。实测高德能提供**餐厅人均价**和多数地点的**开放时间**，但**几乎没有景点门票价**。换用高德 MCP 也一样，因为底层是同一套数据。门票和实时房价在携程、美团等平台手里，接入一般需要合作资质。

- **高德事实数据**：
  - 地点搜索改用详细模式，餐厅显示“高德人均参考 ¥X · 未核实”，酒店有最低价时显示“高德最低价参考”。
  - 评分和开放时间写入地点卡片。
  - DIY、推荐、雨天替换选中的候选会带上这些信息。
- **门票估算**：生成行程或对话修改后，用快速模型估算一次景点门票，免费填 0，不确定就保持未知。
  - 价格标注“模型估算，未核实”；费用小计会注明“含模型估算”。
  - 价格优先级：用户填写 > 高德 > 模型估算，高优先级的价格不会被低优先级覆盖。
- **闭馆提醒**：开放时间里写有“周一不开放 / 周一闭馆”等内容，而行程正好安排在那天时，规则校验会给出警告。节假日规则可能不同，请以官方公告为准。
- **旧行程补充**：结果页“行程可靠性”区域新增“补充价格与开放时间”。它会按高德 ID 查询详情、估算门票，并保存为一个可撤销的版本。接口：`POST /api/trips/{id}/enrich`。
- **限流修复**：地点搜索原来没有限速，并行搜索时容易被高德返回 10021 限流。现在按 `AMAP_POI_QPS`（默认 3）单独限速，遇到限流最多重试 3 次。

实测：用长沙 3 天行程的副本补充，耗时 7.1 秒；17 个地点全部查到，估算了 7 处门票（如岳麓书院 40、天心阁 32；湖南省博物馆、橘子洲估为免费）。用户已填的酒店价保持不变。后端离线测试 88 项通过（新增 6 项），前端生产构建通过。

局限：
- 模型估算的门票可能过时，或与实际票种不符。
- 高德人均价来自用户评价统计，不是菜单价。
- 开放时间是高德登记的文本，不保证与官方实时公告一致。

### 2026-10-10 界面精简

结果页原来顶部有 8 个同等分量的按钮，助手在页面中段，地图在最底部，免责说明重复出现，第一次使用时不知道从哪里开始。本轮只调整布局和交互，功能全部保留。

- **头部**：只保留“编辑行程”“问助手”“更多 ⋯”三个入口。
  - “更多”里是重新校验、补充价格与开放时间、天气与雨天备选、出行准备清单、修改记录、撤销上次修改、导出图片/PDF。
  - 编辑时头部变为“编辑中 · 撤销一步 · 取消 · 保存修改”。
  - 行程概况（天数、景点数、餐数、已知费用）并入标题下面的一行。
- **状态条**：只列需要处理的问题（时间冲突、未校验、缺失交通、规则警告），每条带“去第 N 天”或“重新校验”；轻微提示折叠显示。保存后的“本次修改”自带“撤销这次修改”。
- **两栏布局**：左侧是日期标签加当天卡片，当天的操作（优化这一天、推荐地点）和天气都在卡片头部。右侧固定显示**当天地图**（按时间线顺序编号，酒店标“宿”，切换日期时同步更新）和**旅行助手**（Enter 发送）。窄屏时地图排在行程之后，助手变为底部抽屉，由右下角按钮打开。
- **底部标签页**：整体建议、费用、攻略来源、数据来源说明。各处重复的“未核实 / 以官方为准”说明合并为一处。
- **移除**：左侧导航、手机端快捷导航、统计卡片、装饰标题、动效开关（改为跟随系统的减少动态效果设置），以及每天单独的迷你路线地图（交通耗时已在时间线中显示）。
- **首页**：草稿卡片保留；有已保存的旅行时，顶部显示一行“继续上次的旅行”。
- **修复**：地图改用 2D 模式并关闭地图的键盘操作。原 3D 模式在打开下拉菜单后按键时会抛出 `Pixel(NaN)` 错误；地图的方向键平移也会和日期标签的方向键冲突。地图初始化改为单次执行，并等待容器有尺寸后再进行。

在无头 Chrome 中验证了以下场景：1440px 和 390px 布局、首页“继续上次的旅行”跳转、“更多”菜单、编辑模式、切换日期时地图更新、手机端助手抽屉，过程中没有页面错误。

### 2026-10-10 其他优化

- **缺餐补救**：附近 1.8 公里内没有合适的餐厅时，扩大到 3.5 公里再找一次；仍然没有才留空。
- **雨天备选去重**：连续多个雨天时，每天排第一的室内候选不再重复。
- **按需引入组件**：Ant Design 组件改用 `unplugin-vue-components` 按需引入，结果页专用的组件进入结果页分包。首页首屏 JS 从约 964 KB 降到 851 KB（gzip 后 268 KB），只减少约 12%。剩下的主要是首页本身用到的日期选择器、下拉框、上传、弹窗组件，以及 Ant Design 的样式引擎；要进一步减小，需要把攻略导入面板改为异步加载。按需引入还开启了模板中组件属性的类型检查，因此修正了 6 处日期选择器、数字输入框等组件的类型不匹配。

### 2026-10-10 短距离路段直接按步行

高德公交接口遇到步行可达的短距离时（例如颐和园与旁边的餐厅相距约 345 米），会返回“成功，但公交方案为 0 条”。这不是查询失败。以前的流程是先查公交、再改查步行，提示写着“高德未返回公交方案”，容易被理解为出错，而且每个短路段都多占一次路线限速（默认每秒 1 次）。

现在直线距离在 1 公里以内的路段直接查询真实步行路线，提示改为“距离较近，按步行安排”。1–2 公里之间如果高德仍然没有给出公交方案，照旧改为步行，并说明原因；超过 2 公里仍然明确标为失败，不会用步行冒充。已缓存的路线（最长 6 小时）在缓存过期前仍会显示旧的提示文字。后端离线测试 91 项通过。

### 2026-10-10 具体换乘路线与真实轨迹

此前路线校验只保留了耗时和距离，地图上画的是地点之间的直线。实际上高德公交接口本来就返回了换乘方案、票价和轨迹，只是被代码丢掉了。

- **时间线**：每段交通显示线路摘要，例如“地铁8号线 → 7号线 → 4号线大兴线 · 117 分钟 · ¥5 · 24.8 km”。展开“换乘详情”可以看到逐段说明：步行距离、从哪站哪个口进站、乘几号线往哪个方向、坐几站、在哪站换乘或从哪个口出站、可替代的同段线路，以及打车参考价。
- **地图**：右侧地图沿高德返回的轨迹画路线，乘车部分是蓝色实线并带方向箭头，步行部分是灰色虚线；没有轨迹的旧数据才用淡色直线表示顺序。
- **票价**：当天信息显示“公交地铁约 ¥X”，费用标签页显示全程公共交通票价合计。票价按查询到的方案、成人单程计算，不计入门票、餐饮、住宿的小计。
- **存储**：每段轨迹压缩到最多 160 个点（约 3 KB）。路线缓存换用了新的缓存命名空间，因此已保存的行程需要点“更多 → 重新校验时间”，才能补上这些明细。

实测：用北京 3 天行程的副本重新校验，用时 17 秒，18 段路线全部拿到明细（如天坛 → 颐和园：地铁8号线 → 7号线 → 4号线，¥5，打车约 ¥77）。已在浏览器中确认换乘详情和地图轨迹显示正确，测试副本已删除。后端离线测试 93 项通过，前端类型检查与生产构建通过。

局限：
- 只保存用时最短的一个方案，同一段的其他线路只列出名称。
- 时间是查询时的方案，不预测出行当天的班次和首末班车。
- 票价不含换乘优惠、学生票等差异。

### 2026-10-12 冲突一键调整、出行手册与日历导出

- **时间冲突一键调整**：状态条里的冲突项新增“给出调整方案”。系统会尝试两类调整：
  - 去掉一个可选景点（最多 3 个候选，按停留时长从长到短排列）
  - 按比例缩短可选景点的停留时间（每个不少于 45 分钟）

  每个方案都用真实交通重新校验，标明“调整后可行”或“仍超出约 N 分钟”，可行的排在前面。必去、锁定和已预约的景点不会被改动。点“采用”后保存为可撤销的版本。接口：`POST /api/trips/{id}/days/{date}/fixes`。
- **出行手册（离线网页）**：“更多 → 导出出行手册”会下载一个单独的 HTML 文件。内容包括每天的时间线、地址、开放时间、地铁公交换乘步骤和票价，每个地点带“导航”链接，点开会打开高德地图（安装了 App 就直接打开 App）。适配手机和暗色模式，打印时会隐藏导航按钮。
- **导出到日历（.ics）**：每个有时间的停靠点生成一个日程，使用北京时间，包含地址、坐标和导航链接，可以导入手机或电脑日历。还没校验过时间的行程会提示先重新校验。

实测：用北京 3 天行程的副本测试。第 3 天超出 57 分钟，系统给出 3 个方案，都校验为可行。在浏览器中采用“缩短停留时间”后，状态变为“时间与路线已校验”。导出的手册包含 3 天、21 个停靠点、21 个导航链接，已在 390px 宽度下检查显示；日历文件包含 15 个日程。测试副本已删除。后端离线测试 96 项通过（新增 3 项），前端类型检查与生产构建通过。
