# 后台规划排队、拥塞保护与恢复

本批解决后台规划的无限接收、提交时阻塞事件循环和任务间轮询空等。生产目标仍未完成；本地合成负载不能证明真实模型/地图速度、正式账户隔离或公网抗滥用能力。

## 已实现

- 同一个 SQLite 数据库内，在 `BEGIN IMMEDIATE` 事务中检查并接收任务。默认最多 12 项运行或排队任务，同一浏览器 owner 最多 2 项；新建、对话调整与路线优化共用容量。达到上限返回 HTTP 429、中文原因和 `Retry-After: 15`，本次不插入任务，也不消耗模型或地图调用。
- 已接收请求的幂等重试先于容量检查，容量满时仍返回原任务；不同 owner 或不同请求内容复用 ID 会被拒绝。同一行程原有的重复任务合并和版本检查保留。
- 提交时的数据库事务移到后台线程，返回接收结果前等待事务完成；取消 HTTP 请求也会等当前数据库操作安全结束。若响应丢失，已入库任务仍可被恢复扫描领取。
- 首次领取时检查排队年龄：默认超过 180 秒且从未开始的任务转为“排队超时”，不调用上游。已经开始过的任务仍按租约、最多尝试次数和执行超时恢复，不因创建时间较早丢弃准备好的结果。这不是严格的端到端 180 秒 SLA。
- 任务结束或释放执行权时，主动唤醒当前进程的恢复扫描。扫描数据库也移到后台线程；跨进程变化仍有两秒轮询后备，没有新增 Redis 或跨主机协调依赖。
- 前端区分明确的提交拒绝和网络响应丢失。未接收的 429 清除本次待恢复状态；已接收任务后续遇到 429、503、网络或网关错误时保留恢复信息。刷新恢复时只有确认任务不存在才清除，暂时断网会提示稍后刷新。

配置在 `backend/.env.example`：`PLANNING_MAX_RUNNING=2`、`PLANNING_MAX_PENDING=12`、`PLANNING_MAX_PENDING_PER_OWNER=2`、`PLANNING_QUEUE_TIMEOUT_SECONDS=180`。这些上限不要求把高德 QPS 调高；执行耗时和上游配额限制独立保留。

## 验证证据

运行 `backend/venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -v`：346 项通过，17.530 秒。本批新增 9 项包含容量竞争、运行/排队计数、取消释放、幂等重试、已存行程任务、排队超时、旧任务恢复、SQLite 写锁下事件循环仍可运行，以及 HTTP 429/Retry-After 契约。

前端 36 项测试通过；类型检查、生产构建及完整路由体积门槛通过。错误分类测试验证：未接收的繁忙请求与已接收任务的后续故障不能使用同一种清理策略。没有把这些单元测试描述为新错误状态的浏览器端到端验收。

独立子进程故障复验 `python -X utf8 -m eval.job_reliability` 的 4 项通过：重复执行者只保存一次、准备结果后崩溃可恢复、过期执行者不能写入、另一进程取消后不保存。原始记录在 `backend/eval/results/job-reliability-20261017-175209.json`。

### 三进程合成调度负载

运行 `python -X utf8 -m eval.queue_load`。工具只创建自己的临时数据库和子进程，工作内容为 150ms 等待和公开样例保存，替换模型及门票函数，不向外部服务发请求。每组先让 3 个工作进程就绪，再通过服务函数提交 16 项独立 owner 请求；测试中总容量设为 8、执行容量为 2。这不是 HTTP 压测，HTTP 响应契约由前述 ASGI 测试单独覆盖。

| 指标 | 仅两秒轮询 | 完成后主动唤醒 |
| --- | ---: | ---: |
| 接收 / 拒绝 | 8 / 8 | 8 / 8 |
| 成功且各生成、保存一次 | 8 | 8 |
| 采样最大同时执行数 | 2 | 2 |
| 样本完成耗时 p50 | 2.483s | 0.834s |
| 样本完成耗时 p95（8项样本的最大值） | 6.210s | 1.147s |
| 整组耗时 | 6.327s | 1.242s |

这是同一实现关闭/启用完成唤醒的调度对照，样本小、未做压测统计推断，不能换算为真实规划的提速比例或生产 p95。它验证减少的是任务间的空等，没有通过减少景点、跳过路线校验或删去事实来源改善数字。[保存的验收摘要](QUEUE_ADMISSION_RECEIPT_2026-10-17.json)，原始记录为 `backend/var/queue-load-20261017-175143.json`。

## 尚未完成

容量是共享同一 SQLite 文件的部署内限制，owner 仍是浏览器标识，不是正式认证账户。其他模型接口尚未统一纳入这套后台队列容量，不能宣称全服务已有用户配额或抗滥用保护。真实模型/高德的混合城市负载、冷暖缓存 p50/p95、服务中断与账号级配额仍需单独验收；正式账户认证和更多官方预约/开放来源也仍未完成。
